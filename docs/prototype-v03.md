# Deploy Center 原型 v0.3

本版本在 v0.2 基础上按 14 项审查意见修复，使用 React + TypeScript，保留一种「侧栏工作台」布局。所有执行仍为模拟，不连接服务器，不调用 Maven、JDK、SSH 或 Docker。

## 查看效果

直接用较新的 Chrome 或 Edge 打开 `dist/standalone.html`。页面、React、样式及 Lucide 图标已全部打包，不依赖 CDN，也不需要启动服务器。

如需本地 HTTP 预览：

```powershell
npm ci
npm run build
npm run preview
```

打开 `http://127.0.0.1:4186`。服务只监听本机回环地址，只提供明确列出的构建文件。

## 主要调整

- 服务、服务器、部署目标作为独立实体；同一服务器可被不同服务复用。
- 新增部署目标配置：独立远程文件名、普通 JAR / Docker、启停及重启命令、chmod、停止失败策略、挂载方式、健康检查、默认备份、目录创建及校验策略。
- 每个目标有默认备份策略；部署页「本次策略」单独覆盖，恢复默认不会影响其他目标。
- 普通 JAR 和 Docker 使用不同阶段；Docker 包含容器内 JAR 哈希及稳定性检查，未配置健康检查时标记未验证。
- 三目标混合方式示例按顺序推进，只构建一次；失败停止 / 继续策略实际影响模拟状态机。
- 取消有确认和取消中状态；切换阶段等待当前目标完成检查或回滚，再结束后续部署。
- 任务结束写入可筛选的历史，记录配置快照；缺备份或目标配置变化时禁止直接回滚。
- 增加重试、只重试失败目标、排查命令复制、Docker 日志入口和日志下载。
- 确认弹窗显示产物元信息、Git、目标路径、部署方式、备份名称预览；历史回滚使用独立确认语义。
- React 自动转义用户文本；日志以文本节点渲染，不使用 innerHTML。表单及日志不因定时器整体重建。
- 正式环境确认自动聚焦，弹窗具有焦点陷阱、焦点恢复和可滚动高度；控件有 focus-visible，开关使用 switch 语义。
- 正文 14px，辅助文字至少 12px；提高浅色次要文字和关闭开关轨道的对比度。去除假标题栏和固定最小窗口高度。
- 移除 window.openai、Tweak 和宿主状态事件。`src/` 是唯一产品源码，`dist/` 统一由构建脚本生成。

## 配置和示例

包含 Cordys 两个脚本目标、校园告警目标，以及一个明确标注「新增示例」的 CRM 普通 JAR 备用目标。备用目标使用远程文件名 `crm.jar`，用于展示独立远程文件名、服务器复用和新增的 HTTP 健康检查。三份原脚本目标均默认不配置应用健康检查；版本和上次部署时间显示「未记录」。

配置和历史保存到当前浏览器的 `deploy-center-v2` 本地存储。认证策略可以保存；密码和私钥口令只保留在当前任务内存，不保存、不导出。导入导出可用；导入检查版本、必要字段及引用关系。服务器测试、JDK 检测、容器日志和运行信息仍是原型演示。

正式环境不从历史选择中自动勾选。手动重试包含正式目标时，仍须重新输入 DEPLOY。

## 源码与验证

- `src/App.tsx`：工作台、任务、历史及确认交互。
- `src/forms.tsx`：服务、服务器、部署目标、备份配置组件。
- `src/model.ts`：实体、初始示例、导入校验及安全序列化。
- `src/engine.ts`：可注入时钟的模拟状态机。
- `src/records.ts`：精简历史、版本更新、任务级日志和保留策略。
- `src/credentials.ts`：原型内存凭据会话及按服务器去重。
- `src/validation.ts`：未来真实构建和上传需满足的接受条件。
- `src/ui.tsx`、`src/style.css`：通用交互和布局。
- `scripts/build.mjs`：从唯一源码生成分离资源页面及单文件离线页面。
- `tests/`：状态机与 jsdom 组件交互测试。

开发要求 Node.js 22 或更新版本；依赖版本由 package-lock.json 锁定。

```powershell
npm ci
npm run typecheck
npm test
npm run build
```

本轮执行的类型检查、51 项测试和生产构建结果见下方「v0.3 变更」。本轮未新增浏览器视觉或端到端验收，不沿用 v0.2 的浏览器检查作为本轮结论。

## 与真实部署工具的边界

此次交付是可交互的产品原型，不是已完成的 Windows 部署软件。真实 SSH 双通道、DPAPI 凭据、数据库、文件系统选择器、远程锁、断线恢复、实际文件及容器校验、远程上传清理、安装包仍需后续接入。

Maven 非零退出兼容和无 SHA-256 工具时的弱校验，通过配置与接受条件测试明确规则；模拟引擎没有真实退出码或远程工具探测。未来接入真实引擎时，不能只凭模拟成功状态宣称通过这些检查。

为了便于观察，定时器约每 850ms 推进模拟状态，上传按三个分片模拟。耗时使用实际时间戳计算，不把 tick 次数当作秒数。页面显示的服务器健康、Git、运行版本及未手动选择的产物信息均为示例。浏览器选择实际 JAR 时读取文件名、大小和修改时间，不读取完整 Windows 路径，也不执行 JAR。


## v0.3 变更

### 逐项修复与测试对应

1. **A1 回滚版本更新**：部署与手动回滚成功后统一写入 `task.service.git.commit`，不再沿用发起回滚时的当前版本。版本写回集中在 `src/records.ts`，`src/App.tsx` 调用同一入口。`tests/v03-engine.test.ts` 覆盖先部署 v2、再恢复备份 v1，最终目标版本为 v1。
2. **A2 结构化备份结果**：`src/model.ts` 的 RunTarget 和 History 增加 `backupCreated`；`src/engine.ts` 仅在备份步骤成功时设置，`toHistory` 及 `src/records.ts` 的 `canRollback` 不读取日志文案。`tests/v03-engine.test.ts` 覆盖改标题、删除日志仍可回滚，以及未执行备份时没有备份位置。
3. **A3 保护损坏及旧配置**：`src/model.ts` 将原始字符串写入 `deploy-center-v2.backup-<时间戳>`，原键保留；`src/App.tsx` 顶部提示并提供下载及明确确认按钮，确认前暂停原键写入。若备份因配额失败，界面如实提示并保留原键和内存副本。`tests/v03-engine.test.ts` 覆盖非法 JSON 和旧 schema；`tests/v03-ui.test.tsx` 覆盖页面其他操作也不能覆盖原键、确认后才可保存。
4. **A4 真实耗时与上传展示**：`src/engine.ts` 的 `createTask`、`startTask`、`tick` 接受可注入时钟，任务、目标、构建步骤和目标步骤记录毫秒时间戳及秒数。确认停留时间不计入执行；模拟上传显示百分比与平均速度。`src/ui.tsx`、`src/App.tsx` 展示步骤、任务和历史耗时。`tests/v03-engine.test.ts` 用控制时钟核对累计时间、上传三秒及速度；`tests/v03-ui.test.tsx` 覆盖上传与历史时间表。
5. **A5 默认和本次覆盖分离**：`src/App.tsx` 将部署页选择保存为独立草稿，显示「本次覆盖」及「恢复默认」，只把当前值复制入任务；启动后清除草稿，下一次使用全局默认。设置页才修改默认值。`tests/v03-ui.test.tsx` 覆盖默认值不变、任务确认使用覆盖、恢复默认及下一次准备不继承覆盖。
6. **A6 取消和跳过的历史边界**：`src/engine.ts` 的 `toHistory` 只接受 success、unverified、failed、rolledback。**不记录 skipped 和未修改运行版本的 cancelled 目标**：它们不是版本变更，保留在当前任务视图即可。切换阶段取消仍先完成当前目标，记录其实际成功或失败结果；未执行目标不占版本历史。`tests/v03-engine.test.ts` 覆盖失败后的跳过、构建取消、停服前取消；原有切换阶段取消测试继续运行。
7. **B7 任务日志、精简快照与保留策略**：`src/model.ts` 增加按 taskId 引用的 `taskHistory`，构建日志和构建步骤只存一份；目标 History 只保存目标日志及展示/回滚所需字段。`src/records.ts` 合并导出日志，并按设置保留最新目标记录，默认 200（允许 1–10000）；无引用的任务日志同时删除。`src/App.tsx` 的历史详情分别展示构建日志、目标日志及各自步骤耗时。`tests/v03-engine.test.ts` 检查三目标仅一份构建日志、快照不包含完整配置和清理顺序；`tests/v03-ui.test.tsx` 检查设置与详情分区。
8. **B8 凭据保存方式**：`src/forms.tsx` 增加「每次部署时询问」「保存到 Windows 凭据管理器（正式版实现）」；`src/App.tsx` 在确认时按服务器去重询问密码或私钥口令。选择 Windows 方式也明确提示原型仍需本次输入，原型不实现系统凭据保存。`src/credentials.ts` 将口令与 Task/Database 分离，结束及卸载时清除；`src/model.ts` 只允许凭据策略被序列化。`tests/v03-engine.test.ts` 和 `tests/v03-ui.test.tsx` 覆盖内存清除、去重、密码必填、私钥输入、localStorage 和实际导出调用中无输入口令。JavaScript 的引用清除不等于可证明的物理内存擦除。
9. **C9 脚本一致的示例**：`src/model.ts` 将 Cordys 两个目标和校园告警目标的健康检查设为 none，元数据不再伪造历史健康通过；按方式生成 JAR 命令或 Docker 字段，普通 JAR 不带容器名。只有明确标注「新增示例」的备用目标使用 HTTP。种子历史的日志明确标为新增示例记录。`tests/v03-engine.test.ts` 检查全部目标、启动停止命令及字段隔离；原有期望随需求更新为正确的未验证结果。
10. **D10 Docker 统一原子替换**：`src/engine.ts` 对目录和单文件绑定都执行临时上传、校验、停止容器、原子 mv、启动、容器内哈希及稳定性检查。`src/forms.tsx` 保留挂载方式并增加按路径重新挂载说明。哈希不一致可通过演示注入，按有效备份决定回滚。`tests/v03-engine.test.ts` 分别检查两种序列及哈希不一致导致失败、回滚。
11. **E11 隔离演示控件**：`src/ui.tsx` 提供统一 Demo 容器，`src/style.css` 使用既有颜色的虚线边框及「演示」标签；`src/App.tsx` 的示例产物、旧产物和故障注入，以及 `src/forms.tsx` 的首次部署模拟均受演示模式控制。默认开，设置页可关闭，不改变模拟执行边界。`tests/v03-ui.test.tsx` 检查分组和关闭后隐藏全部这些操作。
12. **E12 完整构建确认**：`src/engine.ts` 快照构建工具、含 Profile 的命令、解析后的工作目录、JDK 名称/路径和预期 JAR 路径；`src/App.tsx` 在重新构建确认中显示，现有 JAR 显示路径、大小、修改时间及早于 Git 提交的提醒。自动模式明确标注原型不探测工具。`tests/v03-engine.test.ts` 覆盖 Wrapper/Maven 上下文；`tests/v03-ui.test.tsx` 覆盖两种确认模式。
13. **E13 带登录方式的排查命令**：`src/validation.ts` 的 `diagnostics` 首行按认证类型生成 `ssh '<别名>'` 或 `ssh -p <端口> '<用户>@<主机>'`，后接容器/文件排查命令，继续统一 shellQuote。`src/App.tsx` 使用该函数复制。`tests/v03-engine.test.ts` 覆盖别名、密码、密钥及名称含单引号的情况。命令只是文本，不自动执行。
14. **E14 JAR 选择限制及接受条件**：`src/App.tsx` 明示浏览器元数据限制及桌面版系统文件对话框；`src/validation.ts` 新增 `inspectJar` / `acceptJar`，检查 ZIP 头、中央目录、偏移和非空 `META-INF/MANIFEST.MF`，支持启动脚本前缀。`tests/v03-engine.test.ts` 覆盖正常、可执行前缀、假头部、截断、缺失/空 Manifest、偏移及名称损坏；`tests/v03-ui.test.tsx` 检查限制说明。**该函数是结构接受条件，不验证完整 CRC 或 JVM 可运行性，暂不支持 ZIP64/分卷；当前浏览器文件选择仍只读元数据，正式引擎接入时需补完整文件读取和完整性校验。**

### 数据格式与运行边界

- 本地键仍是 `deploy-center-v2`，数据 schema 升为 3。旧格式不自动迁移：先备份原文，允许下载；只有用户确认使用示例或主动导入有效新配置才替换原键。
- 历史限额以「目标记录条数」计，不是任务数；同一任务保留任一目标时，其构建日志仍保留一份。已删除历史对应的远程备份不在原型中操作或删除。
- 旧版独立实体、目标级备份、混合部署、取消边界、焦点陷阱/恢复、React 文本转义和配色均保留，对应旧测试继续运行。
- 没有连接真实服务器，没有调用 Maven、JDK、SSH 或 Docker。Windows 凭据管理器、真实 JAR 读取校验和真实远程执行仍属于正式版工作，不把模拟结果当作实际部署成功。
