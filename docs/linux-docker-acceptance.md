# 专用 Linux / Docker 环境手工验收清单

仅使用专用测试服务器和可销毁服务；不得直接以生产服务器作为验收环境。本清单是操作步骤，不代表这些场景已经通过。每次记录：应用版本、Windows 版本、目标系统、JDK/Docker 版本、任务编号、实际结果、日志位置与备份哈希。未执行项填写「未验证」。

## 通用准备

- 创建两个版本的最小测试服务 A/B，响应就绪接口并记录版本；另备慢启动、启动退出、健康返回失败的版本。
- 配置独立测试登录用户、目录和备份目录。确认这些目录可以整体销毁，里面没有业务数据。
- 记录原 JAR 的 SHA-256、大小、权限、所有者、运行状态；Docker 使用固定测试容器并分别准备目录绑定、单文件绑定。
- 应用中配置服务、JDK、服务器、目标，先执行试运行。SSH 指纹通过独立渠道核对；只读诊断前后比较目录、文件哈希和容器状态，确认没有修改。

| 场景 | 前置条件 | 操作步骤 | 预期结果 | 实测记录 |

| 首次部署 | 目标无旧 JAR | 部署 A | 跳过旧文件备份和停止，不因不存在旧文件而失败；生成独立结果 | 未验证 |

| 陈旧锁接管 | 确认原进程退出，锁超出阈值 | 查看高级锁操作，核对持有者并按原安全规则确认接管 | 锁未变化且进程不存活才归档；活进程、时间未到或锁变更时拒绝 | 未验证 |
| 构建/上传阶段取消 | A 运行 | 分别在构建、上传时请求取消并确认 | 本机进程树结束后才完成；远端安全清理自己的临时文件；A 不改变 | 未验证 |
| 切换阶段取消 | 已进入停止/替换/启动 | 请求取消并确认 | 等当前目标校验或回滚到安全边界；不强杀切换；跳过尚未执行目标 | 未验证 |

## Windows 数据目录迁移与升级验收

准备独立的应用配置账户或虚拟机，禁止用现有正式配置试验删除。建立服务、历史、完整日志、产物、加密凭据、迁移备份和临时文件；记录数量和大小。

1. 选择含中文/空格的空目录，核对可写/空间/空目录/路径检查；迁移重启后对比所有数据，测试加密凭据、历史查看与日志导出。
2. 对当前目录、子目录、父目录、系统目录、非空目录、空间不足、不可写目录分别操作，应明确拒绝且原目录不改变。
3. 运行、取消中或未处理中断任务存在时尝试迁移，应阻止。
4. 在复制中取消、结束测试进程、模拟断电；重开后使用原目录或明确恢复提示，不能启用半迁移数据。
5. 迁移后先保留旧目录；重启核对成功后测试显式清理旧目录的路径确认和范围限制。
6. 移走/拒绝访问/损坏新目录后启动，必须有重新指定或使用默认目录的明确选择，不能静默新建空配置。
7. 在虚拟机安装/升级 1.2.0 并测试卸载：默认保留所有数据；选择彻底清理时必须列出自定义数据目录和将要删除的位置。记录 Windows 通知、提示音、任务栏进度与后台点击回到任务页的实际表现。

以上 Windows 原生窗口、安装包和系统通知项目未实测前均标「未验证」。
