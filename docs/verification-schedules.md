# 定时发布验证记录

日期：2026-11-17。当前源码实现桌面端一次性定时发布，不提前上传，不引入常驻服务端。

## 实现与兼容

- 部署确认支持本机时区的发布时间；创建时保存生产环境确认、部署参数及配置摘要，立即准备固定产物。计划与日志独立持久化，配置导入导出不携带计划或凭据。
- 准备复用现有构建和完整 JAR 校验，不创建远程目录、上传、任务锁或停服。准备任务不记录为实际部署成功，不修改线上版本。
- 到点先只读核验全部目标、固定产物、配置、主机身份及线上基线。SSH2 使用已确认指纹；SSH 别名通过系统 OpenSSH 核实有效配置、实际主机指纹及 known_hosts。
- 主进程先持久化唯一关联任务；只读检查完成后，worker 等待主进程持久化实际发布状态并确认，再取得远端锁和上传。异常退出后不会重复创建发布任务；已授权执行的任务继续使用原中断核实机制。
- 目标锁取得后、停服前再次核验线上版本，变化时阻止切换并停止后续目标。普通即时部署保持连续构建和发布；既有备份、替换、健康检查、取消及回滚流程继续复用。
- 等待期间不占执行槽。准备未完成、其他任务或维护操作占用、远端锁占用，最多等到计划时间后 15 分钟；锁每 10 秒重试，不接管。实际部署开始后不再受该启动窗口限制。
- 退出、重启或休眠跨过计划时间不补发。明显系统时间跳变要求重新确认。凭据或认证失败不弹窗等待，也不反复重试认证。
- 待发布计划保护其共享产物；取消后释放计划保护。中断的纯准备任务在取消计划后可按保留策略清理，真实中断部署继续受保护。
- SQLite schema 从 5 升为 6，沿用迁移前备份及事务迁移。数据目录迁移同步调整计划产物路径；配置路径变化后重新确认。数据库暂停迁移期间，调度停止、计划列表保留可读快照。
- 更新和重启先确认待发布计划，再启动更新助手或登记重启，取消退出时继续运行。应用退出前保留现有活动任务保护。

## 真实 Linux / SSH 验收边界

- 使用现有 WSL Ubuntu-24.04 的独立 `/tmp/deploy-center-*` 临时目录运行真实 Bash 脚本，覆盖普通 JAR 的预检、备份、原子替换、启动、失败回滚、取消和收尾。
- 新增只读准备验证：读取实际 SHA-256 / 不存在状态，不创建目录、锁或工作台；远端锁占用能明确识别。验证首次及非首次部署在停服前被外部换包时均不执行停止、启动或替换命令。
- 新增回环 SSH2/SFTP 端到端计划测试：服务器仅监听 127.0.0.1 随机端口，命令转发到隔离 Linux，SFTP 写入其临时目录。准备完成后篡改原始本地 JAR，触发计划，验证实际线上哈希仍等于准备快照，备份、停止、替换、启动、日志确认及锁清理完成，只有一条真实部署历史。
- 上述回环网关为了保持 WSL 后台进程生命周期，会等待同 shell 的 runner 完成；不将此测试称为独立 OpenSSH sshd 的异步会话验收。未配置专用 sshd 的既有集成测试明确跳过。
- Docker 的两种挂载、容器哈希及稳定性分支使用既有 Linux 命令夹具；未连接业务服务器，未执行真实业务 JAR 或真实 Docker 容器部署。
