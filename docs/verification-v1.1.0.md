## 健康检查用法与兼容

在「部署目标 → 编辑 → 健康检查」选择 HTTP/TCP/自定义命令，配置真实地址或命令。推荐先设：启动等待 0–30 秒，最长等待窗口 300 秒，慢项目可设 600 秒，单次超时 5–10 秒，间隔 5 秒。

先完成启动命令及容器文件/进程校验，再静默等待，随后开始窗口内探测。探测通过立即结束；不会固定等满窗口。未配置健康检查仍明确标记「健康未验证」。命令本身的超时单独配置，健康窗口不延长一个迟迟不返回的启动命令。

旧配置仍可读取，数据库 schema、appId、用户目录不变。未编辑的旧健康配置继续按原重试次数执行；编辑目标时显示原策略的等效窗口，保存后转为窗口方式。新目标默认窗口 300 秒。旧记录和未完成任务保持原快照。

本机检查由远端 runner 发起交接；静默等待只执行一次，探测结果交接另留最多 30 秒传输余量。远端和本机时钟独立，不能把传输余量理解为业务健康检查窗口本身。

## 验收边界

- 所有文件、Git、SQLite、JAR、SSH2/SFTP、试运行和 UI 测试均使用专用夹具或 127.0.0.1 随机端口；开发与测试使用隔离数据目录。
- Linux 完整部署流程的 8 项测试、未配置系统 sshd 的 1 项测试继续明确跳过；本轮实际运行的 Bash 健康函数测试不依赖 POSIX 文件权限，不能代替完整 Linux/Docker 部署验收。
- 没有执行业务构建或业务部署，没有重新安装覆盖用户当前正在使用的正式程序或清理其配置。1.0.0 安装/升级/卸载实测记录见 docs/verification.md；1.1.0 的打包程序测试与安装包生成结果在下方记录。
- 安装包未签名。原生模块沿用官方 N-API 预编译版本；本轮没有重新执行需要 C++ Build Tools 的源码重编译。
